3. At the diffusion checkpoint, the agent (probably the planner or another agent) can choose up to k (<=3) tasks to diffuse, each with a similarity index decided by the agent. Since past artifacts are also included, this similarity will depend not only on the task's nature but also on their past run results, such as failure reasons. At different iterations, a task will also have a chance to shuffle the diffusion directions. Once the diffusion operation is complete, the consumed artifacts are dropped and will no longer be used, but they will be kept for audit.
4. The similarity index of the k tasks passes through a softmax gate, which generates a probability distribution used to determine the single target task activated by this source task. 
5. Source tasks will not run in the iteration unless another source task activates them for the next round. 

To-be-discussed problems:

1. Many-source to fewer-target convergence can be useful, but it should be treated as a quorum signal rather than automatic evidence of improvement. If multiple source tasks activate the same target, the target may be central or high-transfer, but it may also reflect scoring bias or premature collapse.

2. The method needs safeguards against over-exploitation. If softmax repeatedly selects the same small set of targets, the workflow may stop exploring hard or under-observed tasks too early.

3. Multi-source context usually exceeds the target budget. The current mitigation is to compact over-budget multi-source artifacts before rendering them into the next target prompt. This should be reported explicitly: number of source artifacts before compaction, tokens before compaction, tokens after compaction, dropped artifacts, and whether compaction preserved the source-specific failure/success signals.

4. Popularity bias is possible. Generic or easy tasks may attract many source activations because they look broadly similar, not because they are the most valuable next attempt.

5. Negative transfer should be tracked explicitly. Multiple weakly related source artifacts can reinforce a wrong plan, so repeated activation should not be assumed beneficial without target outcome evidence.

6. Coverage loss needs an exploration or rescue rule. Maintain a run-count board for each task. Tasks that are constantly ignored, stale, or under-sampled can be periodically rescued into the active set to preserve diversity and avoid permanent starvation.

7. The [-1, 1] similarity range should be treated as signed transfer affinity: +1 means strong expected positive transfer, 0 means uncertain or weak relation, and -1 means likely irrelevant or harmful transfer. This bounded range also prevents a single noisy score from dominating the softmax too strongly.

8. The first random seed batch of round(number_of_tasks / e) tasks should be reported as the exploration cost. It buys enough initial artifact diversity for routing while preserving the remaining tasks for adaptive activation.

9. The main value claim should emphasize faster improvement and campaign-level efficiency, not lower per-row cost. Activated rows may use longer context and more tokens than old whole-family rows, but the workflow is valuable if reward improves faster and reaches a useful reward-per-dollar plateau with fewer total task executions.

10. Required reporting fields: activated targets, skipped tasks, run count per task, source-task count per target, source artifact count per target, similarity scores, softmax probabilities, selected target, consumed artifact IDs, pre-compaction tokens, post-compaction tokens, per-row token cost, total campaign cost, and reward-per-dollar at each checkpoint.

11. Use a last-k active artifacts plus older-summary oblivion mechanism for artifact-store growth. Keep only the most recent k concrete artifacts per task or source-target edge in the active routing store. Older artifacts should be compacted into task-level or edge-level summaries that preserve reusable success patterns, recurring failure modes, targets helped before, targets harmed before, and confidence or freshness. This keeps recent concrete evidence available for softmax routing while preventing the active store from growing without bound. It is related to context-pruning and summarization work such as "Less Context, Better Agents: Efficient Context Engineering for Long-Horizon Tool-Using LLM Agents", which argues that retaining less but more decision-relevant context can improve efficiency for long-horizon tool agents.
